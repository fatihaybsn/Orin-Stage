### Ubuntu 22.04 LTS (Jammy), native

I tested the public PPA on a native x86_64 host. I added the PPA, installed the
package with `sudo apt install orin-stage`, and confirmed that the package came
from the PPA's Jammy source.

The checks included:

- `/usr/bin/ostg` was installed, and `ostg --version` reported `ostg 0.1.0`.
- `doctor` reported 11 PASS, 0 WARN, and 0 FAIL.
- The target catalog loaded successfully.
- The PPA-installed binary opened an existing real Orin Stage state.
- JP6.2.3 target and base reuse succeeded.
- ARM64 `run` execution worked and propagated the child exit code.
- The build capsule worked and propagated the child exit code.
- `inspect` and `storage status` succeeded.
- I did not encounter a traceback or package-resource problem.

I reused existing, previously validated real state during this session. I did
not create a second acquisition, base, or workspace from zero, so this was not
a fresh-from-zero end-to-end acquisition test.

### Ubuntu 24.04.4 LTS (Noble), WSL2

I tested the public PPA in a clean x86_64 WSL2 distribution. I added the PPA,
installed the package, confirmed that it came from the Noble PPA source, and
verified that `/usr/bin/ostg` was present.

The checks included:

- `ostg --version` reported `ostg 0.1.0`.
- Podman 4.9.3 worked.
- `newuidmap`, `newgidmap`, subordinate UID/GID configuration, and
  `podman unshare` passed their checks.
- ARM64 `binfmt` and static `qemu-aarch64` checks passed.
- The target catalog loaded successfully, and CLI help and resources worked
  normally.
- I did not encounter a traceback or package-resource problem.
- `doctor` reported 10 PASS, 1 WARN, and 0 FAIL. The only warning was the
  expected absence of SDK Manager.

I did not run `target ensure`, acquisition, base construction, or workspace
creation in this WSL2 session. This result covers PPA installation plus host,
runtime, and CLI smoke acceptance, not full end-to-end target construction.

## Scope boundary

These checks confirm host operating-system support. They are not physical
Jetson hardware validation and do not cover GPU, DLA, camera, Jetson kernel or
firmware, flashing, performance, or other hardware-dependent behavior.

They also do not change JetPack target support status. They do not make every
JetPack 6 catalog entry end-to-end supported, remove any `validation-pending`
status, or claim implementation or hardware validation for JP6.0 through
JP6.2.2.
